#### WebGL Performance Best Practices (VERIFIED)

| Practice | Impact |
|----------|--------|
| Batch draw calls into fewer, larger calls | Major performance gain ✅ |
| Use texture atlasing | Reduces texture switches ✅ |
| Avoid getError() in production | Causes sync stall ✅ |
| Avoid readPixels() to CPU | Causes GPU finish + stall ✅ |
| Use async data readback | Prevents blocking ✅ |
| Delete objects eagerly | Frees GPU memory ✅ |
| Use texStorage + texSubImage | More efficient than texImage ✅ |
| Use invalidateFramebuffer | Critical for mobile tiled GPUs ✅ |
| Prefer work in vertex shader | Fragment shaders run per-pixel ✅ |
| Use mipmaps for 3D textures | 30% memory but major perf gain ✅ |

- ANGLE_instanced_arrays ✅
- EXT_blend_minmax ✅
- OES_element_index_uint ✅
- OES_standard_derivatives ✅
- OES_vertex_array_object ✅
- WEBGL_debug_renderer_info ✅
- WEBGL_lose_context ✅

### A-Frame VR Best Practices (WebGL)
**Source:** https://aframe.io/docs/1.4.0/introduction/best-practices.html  
**Authority:** A-Frame VR Framework (official documentation)  
**Retrieved:** December 2025

#### Draw Call Budget (VERIFIED)

| Target | Draw Call Limit | Context |
|--------|-----------------|---------|
| VR Applications | **< 300 draw calls** | Rule of thumb for smooth 90fps ✅ |
| Mobile WebGL | **< 100 draw calls** | Mobile GPU constraint (practical) |
| Desktop WebGL | **< 500 draw calls** | Desktop with optimization |

> **Key Optimization:** "Limit draw calls as much as possible. Each geometry, object, model without optimization is generally a draw call. Rule of thumb, try to keep under 300 maximum." - A-Frame Docs

#### Geometry Optimization (VERIFIED)

| Strategy | Description | Impact |
|----------|-------------|--------|
| **Geometry Merging** | Combine static meshes into single geometry | Reduces draw calls ✅ |
| **Texture Atlasing** | Single texture with multiple UV regions | Reduces state changes ✅ |
| **Level of Detail (LOD)** | Lower-poly meshes at distance | Reduces vertex count ✅ |
| **Selective Raycasting** | Raycast specific entities only | CPU optimization ✅ |
| **Object Pooling** | Reuse entities, avoid create/destroy | Reduces GC ✅ |

#### Memory Optimization (VERIFIED)

| Practice | Benefit |
|----------|---------|
| Preload GPU textures | Avoid jank on first draw ✅ |
| Use MeshBasicMaterial for simple scenes | Lower GPU cost than PBR ✅ |
| Bake lighting into textures | Avoid real-time light calculation ✅ |
| Power-of-two texture dimensions | Avoid runtime resize overhead ✅ |
| Minimize JavaScript garbage collection | Prevents VR frame drops ✅ |

#### Single Draw Call Technique (VERIFIED)

> "To draw a large number of objects, you should minimize the amount of WebGL state changes. Draw all objects using the same shader after each other, bundle several objects into a single buffer, push computation to shaders."

| Technique | Performance Impact |
|-----------|-------------------|
| Bundle objects into single geometry | 1 draw call vs N draw calls ✅ |
| Animate in vertex shader (not JS) | Smooth framerate at 1M+ vertices ✅ |
| Reuse buffer objects | Reduces memory churn ✅ |
| Pre-compute in shaders | GPU parallelism benefit ✅ |

### WebGL Context Loss Handling
**Source:** Khronos WebGL Wiki  
**Retrieved:** December 2025

Context loss is expected behavior, especially on mobile. Applications MUST handle:
- `webglcontextlost` event - Prevent default and pause rendering
- `webglcontextrestored` event - Recreate all WebGL resources

> **Note:** All WebGL resources (buffers, textures, shaders, programs) are destroyed on context loss and must be recreated.

#### Source Code Evidence

```javascript

```

> **Critical Finding:** The `audio:[]` array is **EMPTY** - confirming zero audio files are loaded by the site.

